# tp89 依赖台账与版本核查平台

一个本地小工具：把各个项目用到的依赖集中登记起来。页面上先建项目，再往项目下面登记依赖名称、版本、许可、责任人与状态；同一个依赖被两个项目用到时，版本高低一眼能比出来。依赖名写得不合规矩、版本不是三段数字、同一个项目里重复登记同一个依赖，保存时当场就会指出来。

数据全部存在本机的数据文件里，不连数据库，也不调用任何外部服务。

## 技术栈

- 后端：Node.js（>=18）与 Express，前后端同一个进程
- 前端：原生 HTML、CSS 与 JavaScript，页面文件由后端静态目录直接提供，没有构建步骤
- 存储：本地 JSON 文件 `data/db.json`

## 启动方式

```bash
npm install
npm start
```

启动后打开页面地址：<http://localhost:5089>

端口固定为 `5089`，如需临时改动可在启动前设置环境变量 `PORT`。

## 页面怎么用

1. 顶栏右侧可以填当前操作者，填过之后浏览器会记住，新建登记时会把它带进责任人
2. 项目区列出项目名称、负责人、说明与这个项目下已经登记了多少条依赖；可以新增项目，也可以改名、换负责人、删除
3. 依赖登记区顶部可以按项目、状态、许可筛选，再按依赖名、责任人或者备注搜索，右上角刷新按钮重新拉取一次
4. 点新建登记，选好所属项目，填上依赖名称、版本，按需要补许可、责任人、状态与备注；列表里点编辑会把这条登记回填到表单
5. 在编辑表单里把状态改成已弃用时，要填写弃用理由；同名依赖在其他项目仍处于在用或待升时，表单会直接列出这些项目与版本，确认"照旧弃用"后才能保存。已弃用登记的版本、许可与责任人会变成只读；把状态改回在用即恢复，恢复同样记录时间与操作人
6. 任何一步不成立时，页面顶部给出说明，并尽量把问题标到对应的输入项上；删除项目与删除登记都会先确认

项目下面还挂着依赖登记时不允许删除项目，页面上会写清还剩多少条、例如哪几条，先处理这些登记再删。

## 登记口径

- 依赖名称以小写字母或数字开头，可以用小写字母、数字、点、下划线、短横线与斜线，最长 60 个字符；带范围的写法例如 `@types/node` 也按这个口径登记
- 版本写成三段数字，例如 `2.7.18`，需要时可以带一段预发布后缀，例如 `5.0.10-rc.1`
- 许可按实际名称填写，例如 `MIT`、`Apache-2.0`、`BSD-3-Clause`；还没确认的可以留空，列表里会显示成未填
- 责任人可以留空，表示这条依赖还没有定人
- 状态只有三种：在用、待升、已弃用
- 备注用来写为什么用这个版本、有没有待办，最长 200 个字符
- 同一个项目下不允许出现同名的依赖，同一个依赖在不同项目里各登记各的、互不覆盖

## 弃用与恢复

把一条登记标成已弃用不是一次普通保存，要走专门的口径：

1. **弃用必须写理由**：弃用理由为空时当场拒绝，理由最长 200 个字符；新建登记时不能直接选已弃用，要先保存成在用或待升，再通过编辑标弃用
2. **弃用必须有操作人**：取页面右上角的当前操作者，没填操作者不允许弃用或恢复
3. **弃用留痕**：弃用时间、操作人与理由记录在登记上，列表的"弃用 / 恢复记录"列与编辑表单里都能看到
4. **弃用即冻结**：弃用后版本、许可与责任人只能查看、不能修改（所属项目、依赖名与备注仍可改）；如需改动要先恢复成在用
5. **跨项目提示**：弃用前会检查同名依赖是否还在别的项目里登记为在用或待升，如果有，页面列出项目名称、各自状态与版本，操作者可以先去处理那些项目，也可以勾选"照旧弃用"后强制保存
6. **恢复留痕**：已弃用的登记只能恢复成在用（不能直接改成待升），恢复时间与恢复人同样记录在案；恢复之后版本、许可与责任人才重新可以修改。最近一次弃用的理由与恢复痕迹会一直保留在列表里

旧数据里在留痕功能上线前就处于已弃用状态、却没有记录理由的登记，会以其更新时间、责任人与备注补齐弃用信息，并标明理由缺失。

## 数据存储

所有数据写在 `data/db.json`，结构为 `{ "projects": [...], "deps": [...] }`。依赖登记除原有字段外，还带 `deprecationReason`、`deprecatedAt`、`deprecatedBy`、`restoredAt`、`restoredBy` 五个弃用留痕字段。落盘时先把内容写进同名临时文件，再用改名的方式替换正式文件，写入过程中断也不会把数据文件写坏；文件缺失或内容损坏时会自动回落到初始数据。

## 接口一览

| 方法   | 路径                | 说明                                             |
| ------ | ------------------- | ------------------------------------------------ |
| GET    | /api/health         | 服务状态检查                                     |
| GET    | /api/projects       | 项目清单，附带每个项目的依赖条数                 |
| POST   | /api/projects       | 新增项目                                         |
| PATCH  | /api/projects/:id   | 修改项目的名称、负责人或说明                     |
| DELETE | /api/projects/:id   | 删除项目                                         |
| GET    | /api/deps           | 依赖登记列表，支持按项目、状态、许可筛选与关键词搜索 |
| GET    | /api/deps/deprecation-check | 弃用前冲突预检，返回其他项目里同名的在用/待升登记 |
| POST   | /api/deps           | 新增依赖登记（不能直接新建为已弃用）             |
| GET    | /api/deps/:id       | 查看单条依赖登记                                 |
| PATCH  | /api/deps/:id       | 修改依赖登记                                     |
| DELETE | /api/deps/:id       | 删除依赖登记                                     |

接口出错时统一返回 `{ "error": { "code": "...", "message": "...", "field": "..." } }`，其中 `field` 用于让页面把问题标到具体的输入项上。
